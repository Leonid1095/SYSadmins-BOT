# Сторож на Agent SDK — дорожная карта

Статус: в работе. Обновляется по мере прохождения этапов.

## Зачем

`monitor.sh` умеет замечать, что что-то сломалось, но не умеет объяснять. Он шлёт
«Контейнер не запущен» и замолкает — дальше человек лезет на сервер и разбирается
сам. Сторож закрывает именно этот разрыв: он объясняет, что произошло, чем это
грозит, и предлагает починку кнопкой.

## Принцип

Детерминированный код собирает факты и решает, что изменилось. Модель просыпается
**только на дельте** — на смене состояния, а не по расписанию. Диск, третьи сутки
стоящий на 81%, молчит. Диск, ушедший с 80% на 91% за пять минут, будит модель.

Из этого следует главное свойство: в спокойный день сторож не тратит ни одного
токена и не шлёт ни одного сообщения.

## Поток

```
systemd timer (*/5 мин)
        │
        ▼
   collect ── детекторы, без LLM → facts.json
        │
        ▼
   delta   ── сравнение с прошлым снимком
        │
        ├── дельты нет → выход (0 токенов, 0 сообщений)
        │
        ▼ дельта есть
   deepen  ── детерминированный добор контекста под тип проблемы
        │     (упал юнит → его последние строки journalctl)
        ▼
   analyst ── Claude Agent SDK, подписка Max, READ-ONLY
        │     вход: дельта + факты + добранный контекст
        │     выход: severity, объяснение, набор действий из каталога
        ▼
   notify  ── @plgames_admin_bot → владельцу, с кнопками
        │
        ▼ владелец нажал кнопку
   remedy  ── исполнение ОДНОГО действия из каталога, с аудитом
```

## Модель безопасности

Инцидент с утечкой токена показал цену беспечности, поэтому границы жёсткие.

**1. Модель ничего не исполняет.** У аналитика нет `Bash`, `Write`, `Edit`.
Только `Read`/`Grep`, и только внутри каталога инцидента, куда наши же детекторы
положили факты. Read-only здесь — не обещание в промпте, а отсутствие инструмента.

**2. Модель не придумывает команды.** Она выбирает действия из фиксированного
каталога по идентификатору. Строку команды формирует наш код, не модель.

**3. Ничего не выполняется без человека.** Модель предлагает — владелец нажимает.
Автоматической починки нет ни в каком виде.

**4. Содержимое логов — это данные, а не инструкции.** В nginx и fail2ban пишут
посторонние: строки в логах сочиняет атакующий. Аналитик получает их как
недоверенный текст и предупреждён об этом в системном промпте. Поскольку
исполнять он всё равно ничего не может, инъекция в худшем случае портит совет.

**5. Разделение привилегий.** Бот работает под `plg` и не имеет root. Действия
исполняет отдельный root-хелпер, который заново проверяет идентификатор действия
по каталогу и игнорирует всё, что пришло сверх него. Доступ к хелперу — одна
строка sudoers на один скрипт.

**6. Только владелец.** Бот отвечает исключительно на `OWNER_ID`; остальные
update'ы отбрасываются молча. Мультиарендный слой (регистрация чужих серверов,
выдача ключей в чат) убирается.

## Этапы

Каждый этап заканчивается коммитом и проверкой. Без прохождения проверки
следующий этап не начинается.

| # | Этап | Проверка |
|---|------|----------|
| 0 | Секреты только в env | ✅ сделано, коммит `0a79e67` |
| 1 | `collect` — детекторы в JSON | запуск на живой машине, схема фактов валидна |
| 2 | `delta` — снимки и сравнение | подсунуть искусственный снимок, увидеть дельту |
| 3 | `analyst` — Agent SDK, read-only | прогон на реальной дельте; попытка выйти за read-only отбита |
| 4 | `remedy` — каталог и root-хелпер | хелпер отвергает действие вне каталога |
| 5 | `notify` + кнопки в боте, owner-only | сообщение с кнопками доходит; чужой ID игнорируется |
| 6 | systemd timer и hardening | таймер срабатывает, юнит с ограничениями |
| 7 | Финальная проверка и push | сквозной прогон, отсутствие секретов, git |

## Каталог действий (этап 4)

Каталог намеренно узкий. Действие попадает в него, только если оно обратимо и
его последствия предсказуемы.

- `restart_unit` — рестарт systemd-юнита из белого списка
- `restart_container` — рестарт docker-контейнера из белого списка
- `prune_builder` — очистка docker build cache (главный пожиратель диска)
- `vacuum_journal` — усечение журнала systemd по времени
- `nothing` — «ничего не делать», фиксируется в аудите наравне с остальными

Удаление данных, правка конфигов, любые операции с сетью и SSH в каталог
не входят и входить не должны.

## Что осознанно не делаем

- Автоматическую починку без человека.
- Произвольные shell-команды через бота — ни в каком виде, включая «только для
  владельца». Утечка токена не должна давать root.
- Дублирование детекторов: факты собираются рядом с `monitor.sh`, а не вместо
  него; текстовые алерты и резервные каналы ntfy/email остаются как есть.
